# 🗺️ Дорожная карта развития FinRest (Product Roadmap)

Комплексный план эволюции финансового сервиса для ресторанного бизнеса (HoReCa) — от локального прототипа до масштабируемого SaaS-продукта.

---

## 🟢 Фаза 1: Инженерный фундамент и локализация (152-ФЗ) — ВЫПОЛНЕНО
- [x] **Персистентность в PostgreSQL 17:** развёрнута локальная база данных, настроена схема Prisma 7 (`User`, `Venue`, `Transaction`, `DeduplicationPair`, `FileUpload`, `InventoryItem`, `CashBalance`).
- [x] **Серверная архитектура:** типизированные репозитории и Server Actions, замена `localStorage` на работу с СУБД.
- [x] **Автоматизированное тестирование:** 25 сквозных тестов (`node:test`, репозитории, эквайринг, парсеры).

## 🟢 Фаза 2: Парсинг HoReCa и дедупликация — ВЫПОЛНЕНО
- [x] **Банковский парсер 1CClientBankExchange:** поддержка выгрузок Т-Банка, Сбера, Точки, Альфа-Банка (.txt).
- [x] **Умный автокатегоризатор:** словарь ресторатора (`food`, `bar`, `salary`, `rent`, `utilities`, `marketing`, `household`, `services`).
- [x] **Алгоритм дедупликации:** поиск пересечений между кассой iiko, банком и сейфом с допусками по времени и сумме.
- [x] **Финансовый движок:** автоматический расчёт управленческих отчётов ОПиУ (P&L) и ДДС (Cash Flow) с экспортом в Excel.
- [x] **Триада финучета (Управленческий баланс):** операционный баланс, чистый оборотный капитал (NWC), светофор текущей ликвидности (CR), расчет безопасных дивидендов с операционным буфером и экспорт в Excel.

## 🟢 Фаза 3: Безопасность, роли и Multi-tenancy — ВЫПОЛНЕНО
- [x] **Аутентификация:** безопасное хеширование паролей (`bcryptjs`) и сессионные токены (`JWT / HS256`) в защищённых cookies.
- [x] **Ролевая модель (RBAC):** разграничение прав (`OWNER` — владелец, `MANAGER` — управляющий, `ACCOUNTANT` — бухгалтер).
- [x] **Интерфейсы входа:** экраны `/login` и `/register` с быстрым выбором демо-ролей и защитой данных по 152-ФЗ.

## 🟢 Фаза 4: Прямой коннектор iikoCloud API — ВЫПОЛНЕНО
- [x] **iiko API Client:** подключение к облачному API iiko (`https://api-ru.iiko.services/api/1`) и песочный mock-режим.
- [x] **Фоновая синхронизация:** автоподтягивание кассовых смен, номенклатуры и остатков заведения.
- [x] **Панель управления iiko:** тестирование токена, выбор ресторана и ручной запуск в настройках.

## 🟢 Фаза 5: Контейнеризация и производственный деплой — ВЫПОЛНЕНО
- [x] **Multi-stage Dockerfile:** оптимизированный standalone-образ Next.js на Alpine Linux.
- [x] **Стек Docker Compose:** согласованный запуск `app`, `postgres:17-alpine` и `nginx:alpine`.
- [x] **Скрипты автоматизации:** скрипт деплоя в одну команду `deploy.sh` и ежедневные бэкапы с ротацией `backup-db.sh`.
- [x] **Документация:** пошаговый гайд по запуску на Selectel, Timeweb Cloud и Yandex Cloud (`DEPLOYMENT.md`).

## 🟢 Фаза 6: Telegram-бот для владельцев и управляющих — ВЫПОЛНЕНО
> **Цель:** Перенести ключевые операционные сценарии в карман ресторатора, где он проводит 90% рабочего времени.
- [x] **Вечерний Flash-отчёт:**
  - Автоматическая сводка в 23:30 (cron `/api/cron/flash-report`): выручка за день, расходы, факт наличных в сейфе, чистая прибыль за смену и предупреждения о расхождениях.
- [x] **Алерты о найденных дубликатах:**
  - Сообщение с инлайн-кнопками: `[Объединить]`, `[Это разные расходы]` для моментального разрешения задвоений с мобильного.
- [x] **Быстрый ввод расходов наличными:**
  - Шеф-повар или админ пишет боту текст: *"14500 зелень и овощи Фудсити нал"* — бот распознаёт сумму (включая пробелы/разделители тысяч), контрагента и категорию и сохраняет в ДДС.
  - Двухступенчатое распознавание фото чеков (OCR): 54-ФЗ QR-код (<80мс, 0 токенов, 100% точность) и Multimodal Vision LLM fallback для рыночных накладных и товарных чеков.
- [x] **Интерфейс в веб-приложении:**
  - Вкладка подключения в Настройках с мгновенным переходом по deep-link и 6-значным PIN-кодом (482-195).

## ⚪ Фаза 8: ABC/XYZ-анализ меню и контроль фудкоста (Food Cost Engine)
> **Цель:** Помочь шеф-повару и управляющему максимизировать чистую маржу блюд.
- [ ] **Матрица меню Касаваны-Смита:**
  - *Звёзды* (высокая маржа, высокий спрос) — драйверы прибыли.
  - *Рабочие лошадки* (низкая маржа, высокий спрос) — кандидаты на повышение цен или оптимизацию рецептуры.
  - *Загадки* (высокая маржа, низкий спрос) — продвижение через официантов и маркетинг.
  - *Собаки* (низкая маржа, низкий спрос) — кандидаты на вывод из меню.
- [ ] **Расчёт фактического фудкоста:**
  - Сравнение нормативного фудкоста (по калькуляционным картам) с фактическим (по закупкам и списаниям).
  - Выявление перерасхода и скрытых краж на кухне/баре.
